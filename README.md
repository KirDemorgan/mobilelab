# Задания 1–3 — карта, изображения, SQLite, геолокация и уведомления

Приложение на Expo SDK 57, React Native и TypeScript для iOS.

## Запуск

Нужны Node.js 22.13+ (LTS) и Expo Go с поддержкой SDK 57 на iPhone.

```sh
npm install
npm start
```

Подключите компьютер и телефон к одной сети и откройте QR-код камерой iPhone. Для симулятора iOS на macOS: `npm run ios`.

```sh
npm run typecheck
npm test
```

Тесты запускаются через tsx и проверяют расстояние, радиус 100 метров, защиту от дублирования, несколько меток, выход и повторный вход, удаление метки, запрет отправки в фоне и восстановление после ошибок уведомлений. Нативные GPS и уведомления проверяются отдельно на устройстве. Файл тестов базы данных, упомянутый в предыдущем README, в ветке lab2 отсутствовал.

## Использование

1. Удерживайте точку на карте, чтобы добавить маркер.
2. Нажмите на маркер, чтобы открыть координаты и фотографии.
3. Добавляйте фотографии через системную галерею и удаляйте кнопкой под изображением.
4. Кнопка «Удалить маркер» удаляет маркер и связанные изображения после подтверждения.
5. Маркеры и фотографии сохраняются после перезапуска приложения.
6. Разрешите доступ к местоположению и уведомлениям. Синий маркер «Вы здесь» показывает текущую позицию.
7. При приближении на 100 метров к сохранённой метке появляется локальное уведомление.

## Задание 3: реализация и настройка

Добавлены `expo-location` и `expo-notifications` версий для SDK 57. Они устанавливаются обычной командой `npm install`. В `app.json` настроены плагины и текст запроса геолокации для собственной iOS-сборки; в Expo Go системный запрос относится к Expo Go. Push-токены и сервер не нужны.

`src/context/location-context.tsx` управляет разрешениями и подпиской над навигацией, поэтому просмотр фотографий не останавливает GPS. Используется `watchPositionAsync`: точность Balanced, расстояние между обновлениями 5 м, интервал 5000 мс (интервал применим на Android; на iOS частоту определяет система). При уходе в неактивное состояние подписка удаляется, при возврате разрешения и службы проверяются снова, ожидаются свежие координаты. Ошибки и отказ разрешений показываются на карте с кнопкой повторной попытки. После отказа разрешение можно включить в настройках устройства.

`src/services/proximity.ts` вычисляет расстояние по формуле Хаверсина. Радиус — 100 м включительно. `Map<markerId, notificationId>` хранит активные уведомления в памяти. Проверки выполняются последовательно, чтобы быстрые GPS-события не создавали дубликаты. Пока пользователь остаётся в зоне, повторов нет, даже если он вручную смахнул уведомление. При выходе или удалении метки уведомление отменяется и убирается из центра уведомлений, затем запись удаляется из памяти. Новый вход снова вызывает уведомление. Сбой одной метки не блокирует остальные, неуспешная операция повторяется при следующем обновлении.

`src/services/notifications.ts` запрашивает разрешения и включает показ локальных уведомлений в активном приложении. При новом запуске старые показанные уведомления приложения с префиксом `marker-proximity-` очищаются; после получения GPS начинается новая сессия. Переход в фон сохраняет карту активных уведомлений в памяти, а полное завершение приложения или перезагрузка устройства сбрасывает её.

## Проверка задания 3

1. На iPhone разрешить геолокацию и уведомления. Проверить синий маркер при движении. Открыть детали сохранённой метки: отслеживание должно продолжаться.
2. Для воспроизводимой проверки открыть Expo Go в iOS Simulator на macOS и задать координаты через меню Features → Location → Custom Location. Например, создать метку в `55.750000, 37.610000`; позиция `55.750500, 37.610000` внутри зоны (около 56 м), `55.752000, 37.610000` снаружи (около 222 м). Для физического iPhone можно пройти маршрут; настройки фиктивного GPS Android к нему неприменимы.
3. Войти в зону: одно уведомление. Несколько раз изменить координаты внутри зоны: повторов нет. Выйти: уведомление исчезает из центра уведомлений. Войти снова: новое уведомление.
4. Создать две близкие метки: должно прийти по одному уведомлению на каждую. Удалить одну: её уведомление исчезает, второе остаётся.
5. Отказать в каждом из разрешений отдельно, отключить службы геолокации. Проверить сообщения, затем включить разрешения/службы и нажать повторную попытку. Отказ уведомлений не мешает отображению местоположения.
6. Свернуть приложение, изменить GPS, вернуть приложение: в фоне новые проверки не выполняются; после возврата свежая позиция определяет очистку или отправку. При возврате в той же зоне повторов нет.
7. Завершить приложение или перезагрузить устройство с активным уведомлением. После запуска старое уведомление очищается; если пользователь снова в зоне, допускается одно новое уведомление новой сессии.
8. Проверить с приблизительным местоположением iOS и точным GPS: при низкой точности граница зоны может срабатывать неточно.

Фоновый GPS не реализован: функциональные требования ограничивают обновления активным приложением. В фоне выход из зоны обнаруживается только после возврата. Точность зависит от GPS; колебания около 100 м могут считаться выходом и новым входом. Доставка и внешний вид уведомлений зависят от разрешений и настроек iOS (например, режима фокусирования). Автоматические тесты не проверяют системные диалоги, доставку и физический GPS. Дополнительные функции сверх задания 3 не добавлены.

Документация: [Expo Location SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/location/), [Expo Notifications SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/notifications/).

## Структура

- `src/app/` — карта, детали и навигация.
- `src/context/database-context.tsx` — подключение к SQLite, общее состояние, CRUD, ошибки и загрузка.
- `src/database/schema.ts` — описание таблиц Drizzle, создание базы и версия схемы.
- `src/database/operations.ts` — CRUD-запросы через Drizzle ORM.
- `src/database/image-files.ts` — хранение копий фотографий в папке приложения.
- `src/components/image-item.tsx` — изображение и кнопка удаления.
- `src/types.ts` — типы данных и параметров маршрута.

## Схема базы данных

База `markers.db` хранится локально на устройстве.

```sql
CREATE TABLE markers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE marker_images (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    marker_id INTEGER NOT NULL,
    uri TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (marker_id) REFERENCES markers (id) ON DELETE CASCADE
);
```

При каждом подключении включаются внешние ключи (`PRAGMA foreign_keys = ON`) и режим WAL. Версия хранится в `PRAGMA user_version`: для новой базы обе таблицы и версия 1 создаются одной транзакцией. При повторном запуске таблицы сохраняются. Более новая неизвестная версия вызывает ошибку без изменения данных.

Контекст предоставляет addMarker, deleteMarker, getMarkers, addImage, deleteImage, getMarkerImages, а также isLoading, isReady, error и retry. Массив markers в памяти используется для отображения; источником сохранённых данных является SQLite. ID генерирует база.

В поле uri хранится относительное имя копии фотографии в Documents/marker-images. Полный путь вычисляется при отображении. Это позволяет не зависеть от временного кэша ImagePicker и абсолютного пути контейнера приложения. Оригиналы в галерее не изменяются.

## Ошибки и транзакции

- Ошибка подключения или инициализации показывает сообщение и кнопку повторной попытки.
- Все операции проходят через контекст по одной. Во время работы кнопки изменения данных отключены.
- Изменение базы и чтение обновлённых данных выполняются в одной транзакции. При ошибке, в том числе нарушении ограничений, выполняется откат; состояние экрана обновляется только после commit.
- Удаление маркера каскадно удаляет строки изображений в той же транзакции.
- При ошибке операции появляется сообщение с возможностью переподключиться. Можно также повторить действие; автоматического повторения записи нет.
- При неудачном сохранении изображения его новая копия удаляется. При успешном удалении записей очищаются связанные файлы. SQLite и файловая система не имеют общей транзакции: при аварийном завершении или ошибке удаления файла может остаться неиспользуемая копия.
- При размонтировании провайдера соединение закрывается после завершения инициализации и текущей операции.
- В режиме разработки операции и ошибки записываются в консоль.

Подключение, инициализация и транзакции используют асинхронный API expo-sqlite. Сам драйвер Drizzle для Expo выполняет короткие запросы синхронно; публичные методы контекста возвращают Promise. Для большого объёма данных потребовались бы постраничные выборки. Пакет expo-sqlite содержит собственные TypeScript-типы, поэтому @types/sqlite3 из примера задания не нужен: он относится к другой библиотеке.

## Почему Drizzle ORM

Drizzle имеет драйвер Expo SQLite и позволяет описывать таблицы и запросы на TypeScript. Типы маркеров и изображений выводятся из описания таблиц через $inferSelect. Значения в insert и where передаются параметрами. Прежние запросы с плейсхолдерами ? также были параметризованы: ORM добавлена ради типизации и удобства, а не для исправления SQL-инъекции.

ORM используется для всех CRUD-операций. Создание таблиц и PRAGMA оставлены в существующей инициализации версии 1, чтобы сохранить совместимость с установленной базой. При изменении таблиц нужно обновлять описание Drizzle и добавлять соответствующее изменение в инициализацию с повышением версии. Drizzle Kit и генерация миграций для текущих двух таблиц не подключены.

Drizzle — единственное реализованное дополнение из необязательного раздела задания.

## Проверка на iPhone

1. Создать два маркера и добавить фотографии к каждому.
2. Полностью закрыть приложение и открыть снова: координаты и фотографии должны сохраниться.
3. Удалить одну фотографию и проверить результат после перезапуска.
4. Удалить маркер с фотографиями: второй маркер и его фотографии должны остаться.
5. Отменить выбор фотографии и удаление маркера: данные не должны измениться.
6. Открыть несуществующий маршрут или ID: должен быть доступен возврат на карту.

## Ограничения

- Удаление приложения удаляет его локальные данные. Синхронизации с сервером нет.
- Для загрузки карты нужен интернет. Таймаут проверяет готовность компонента карты, но не гарантирует загрузку всех тайлов.
- Для стандартной Apple Maps в Expo Go API-ключ не нужен.
